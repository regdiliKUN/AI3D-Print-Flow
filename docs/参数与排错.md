# 参数与排错

> v1.5.0 起日常启动使用 `AI3D-Print-Flow.exe`，桌面快捷方式也指向它；`start.cmd` 只保留为兼容入口。exe 是轻量启动器，仍依赖同目录的 `runtime\node.exe` 和 `app\`，不是单文件应用。

本文分三部分：

1. **参数**：每个预设、每个关键节点在调什么。
2. **校验**：怎么看 Blender/STL 报告，什么算合格。
3. **排错**：按报错现象查原因。

---

## 1. 显存档位

| 预设 | TRELLIS.2 上采样 | WTiVo 输入/输出 | 代理点 | Quad Reconstruct | 显存 | 内存 | 适用 |
|---|---|---|---|---|---|---|---|
| **1K** | 1024 | 1024 / 1024 | 8,000,000 | 启用 | 6–8 GB | 16 GB | 低显存、简单角色 |
| **1.5K** | 1536 | 1536 / 1536 | 12,000,000 | 启用 | 8–16 GB | 16–32 GB | 推荐；速度/细节平衡 |
| **2K** | 2048 | 2048 / 2048 | 25,000,000 | **bypass（mode 4）** | 16 GB+ | 32 GB+ | 最高细节；大模型 |

### 怎么选

- 第一次跑：**1.5K**。
- 显存 8 GB 以下：**1K**，如果还 OOM，把代理点降到 6M 或更低。
- 显存 16 GB+ 且内存 32 GB+：再试 **2K**。
- 角色简单、只打小尺寸：1K 足够。
- 龙、毛发、鳞片、复杂盔甲：1.5K 起步。

### 2K 的特殊性

2K 不是把 1.5K 参数乘 1.33。官方 README 明确说：

- 2K 下保留 Quad Reconstruct 会让 WTiVo 网格到约 **8500 万面**，内存约 **17 GB**；
- LODTailor 减面会破坏水密；
- 所以 2K 工作流把 Quad Reconstruct 设为 **bypass**；
- 直接用 25M 代理点，得到约 **4300 万面** 的水密网格。

本控制台注入 2K 时不会改 Quad 的 bypass 状态；1K/1.5K 会改它的分辨率。

## 2. Qwen-Image 2.1 参数

| 参数 | 本工具默认 | 范围/建议 | 作用 |
|---|---|---|---|
| 提示词 | 主体 + 风格模板 | 越具体越好 | 决定内容和轮廓 |
| 画幅 | 1:1 | 1:1 最适合单体摆件 | 方形好构图 |
| 百万像素 | 2K=4 MP，1.5K=2.25，1K=1 | 跟显存走 | 分辨率 |
| 宽/高 | 2048/1536/1024 | 与预设一致 | 实际像素 |
| CFG | 1 | 官方模板默认 | 提示词约束强度 |
| 步数 | 25 | 20–30 | 细节/时间 |
| 批量 | 1 | 1–4 | 一次出几张 |
| 种子 | 随机 | 固定可复现 | 结构变化 |
| 输出前缀 | `AI3D/Qwen_2k` | 可改 | 输出目录 |

### 提示词建议

```text
<主体>，<姿态/构图>，<材质/细节>，
miniature statue, compact single subject, integrated circular base,
clean silhouette, neutral background, no text, no watermark,
designed for 3D printing
```

避免：

- 多主体互相遮挡；
- 极细的独立飘带/发丝；
- 透明、镜面、强反光材质（3D 重建不擅长）；
- 复杂背景（会被去背景，但可能带碎块）；
- 文字、logo、水印。

### 生成时间

视频说 RTX 5080 上 2K 约 **473 秒**，但很可能是 **47.3 秒** 的转写/口误。实际时间取决于：

- 显卡；
- 分辨率；
- 步数；
- 是否第一次加载模型（首次会慢很多）；
- 系统内存/显存是否被其他程序占用。

不要用视频数字做硬性预期。

## 3. PixelArtistry 水密工作流参数

### 3.1 节点顺序

```text
LoadImage
  → RemoveBackground (BiRefNet)
  → Pixal3D / Trellis2 Conditioning
  → Trellis2UpsampleStage
  → [MeshReconstructWithQuad]  ← 1K/1.5K 启用，2K bypass
  → WTiVoNativeMeshToMesh
  → VoxelToMesh
  → LODTailorTheMeshTrimmer (Blender)
  → WTiVoFastMergeByDistance
  → Save3DAdvanced
```

### 3.2 关键参数

| 参数 | 位置 | 默认 | 怎么调 |
|---|---|---|---|
| 图片 | `LoadImage` | 你的图 | 控制台自动复制到 `ComfyUI/input` |
| TRELLIS.2 开关 | `PrimitiveBoolean` | true | 控制台强制打开 |
| 上采样分辨率 | `Trellis2UpsampleStage` | 1536/2048 | 跟随预设 |
| Quad 分辨率 | `MeshReconstructWithQuad` | 1536 | 1K/1.5K 注入；2K 保持 bypass |
| WTiVo 分辨率 | `WTiVoNativeMeshToMesh` | 1536/2048 | 跟随预设 |
| 代理点 | `WTiVoNativeMeshToMesh` | 12M/25M | 显存不够就降 |
| `lambda_fill` | `WTiVoNativeMeshToMesh` | 20 | 小洞 10–20，大洞 30–40 |
| LODTailor 面数 | `LODTailorTheMeshTrimmer` | 6,000,000 | 想更轻可降，但别太低 |
| LODTailor 相对体素 | 同上 | 0.001 | 越小越细，越慢 |
| Blender 路径 | `PrimitiveString` / LODTailor | `blender` | 填完整路径，**去掉引号** |
| 输出前缀 | `Save3DAdvanced` | `3d/AI3D_*` | 控制台自动加时间戳 |

### 3.3 WTiVo 调参思路

WTiVo 的目标是“闭合”，不是“更漂亮”。调参优先级：

1. **先换种子**：很多破洞是单视图猜测失败，换种子最快。
2. **再调 `lambda_fill`**：
   - 10–20：小洞；
   - 20：默认；
   - 30–40：大洞/断裂；
   - 太高：把手指缝、龙角间隙等本该保留的开口封死。
3. **再降代理点**：显存不够时，降代理点比降分辨率更直接。
4. **最后体素重建**：控制台后处理的 voxel 模式是“保底”，不是首选；它会让细节变圆、薄片变厚。

### 3.4 什么时候绕过 LODTailor

视频里演示了复制 `Save 3D Model` + `Mesh to 3D File`，把 WTiVo 输出直接保存，绕过水密流程和 LODTailor，得到高面数原始版本。

适用：

- 你只想要最高细节，不在乎 4000 万面；
- 你有足够内存和切片性能；
- 你想对比 LODTailor 是否吃掉了细节。

不适用：

- 16 GB 内存；
- 切片软件打开就卡死；
- 你需要快速迭代。

## 4. Blender 后处理参数

控制台调用：

```bat
blender.exe --background --factory-startup --python-exit-code 2
  --python blender\postprocess.py -- ^
  --input model.glb ^
  --output model.stl ^
  --report report.json ^
  --target-height 80 ^
  --repair auto ^
  --decimate 0 ^
  --keep-largest 1
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--input` | 必填 | `.glb` / `.gltf` |
| `--output` | 自动 | `workspace/stl/<名字>_<时间>.stl` |
| `--report` | 自动 | `workspace/reports/<名字>_<时间>.json` |
| `--target-height` | 80 | 最大边缩放到该毫米数；0 = 不缩放 |
| `--repair` | auto | auto / fill / voxel / none |
| `--decimate` | 0 | 0–1，1 = 保留 100%，0.5 = 保留 50% |
| `--keep-largest` | 1 | 只保留主部件 + 占比 ≥1% 的部件 |

### 修复模式怎么选

| 模式 | 做什么 | 适合 | 风险 |
|---|---|---|---|
| `auto` | 先补洞；仍不水密再体素重建 | 大多数情况 | 体素可能让细节变圆 |
| `fill` | 只补边界洞 | 小破洞、想保细节 | 大洞/薄壳修不好 |
| `voxel` | 体素重建 | 大破洞、碎块、非流形 | 薄片变厚、细节丢失 |
| `none` | 不修复 | 只缩放/清理 | 不水密就不能切片 |

### 减面

- 先 0（不减）。
- STL 超过 400 万面、CHITUBOX 卡顿时，再试 0.75 / 0.5。
- 减面后必须重新看水密；有时减面会制造新洞。
- 打印微缩模型，200–400 万面通常足够；4000 万面是“原始高模”。

### 目标高度

- 80 mm 是视频里龙的大致微缩尺寸，也是本工具默认。
- 你的打印机平台 200×120 mm，不代表模型要占满；微缩模型 60–100 mm 更好加支撑。
- 目标高度是**最大边**，不是 Z 高度。扁长模型会被最大边限制。
- 设 0 表示不缩放，保留 GLB 原始单位。

### 报告字段

`workspace/reports/*.json` 里常用：

| 字段 | 含义 |
|---|---|
| `final.dimensionsMm` | 最终 XYZ 尺寸（mm） |
| `final.triangles` | 三角面数 |
| `final.volumeMm3` | 体积（mm³） |
| `final.boundaryEdges` | 边界边数 |
| `final.nonManifoldEdges` | 非流形边数 |
| `final.watertight` | 是否水密 |
| `voxelShellWarning` | 体素是否疑似薄壳 |
| `removedParts` | 删掉的碎块数量 |
| `repair` | 实际使用的修复方式 |

### 薄壳警告

体素重建后如果体积接近 0，可能是生成了“薄壳”而不是实体。看到：

```text
voxelShellWarning: true
```

处理：

1. 改用「仅补小洞」；
2. 或提高体素尺寸/降低分辨率；
3. 在 CHITUBOX 里用截面检查壁厚；
4. 必要时回到 Blender 手动 Solidify。

## 5. STL 校验指标

控制台用流式解析统计：

| 指标 | 合格 | 说明 |
|---|---|---|
| 三角面 | > 0 | 0 表示文件坏/空 |
| 尺寸 | 与目标高度误差 ≤ 8% | 超过会警告 |
| 边界边 | **0** | >0 表示有洞/开放边 |
| 非流形边 | **0** | >0 表示一条边被 >2 面共享 |
| 体积 | >0 | 接近 0 可能是薄壳/法线翻转 |
| 文件大小 | 合理 | 数千万面会很大 |

### 注意

- STL 不保存单位，只有数值。`80` 是“80 个单位”，切片器通常按 mm 解释。
- 边界边 0 不等于一定能打印；还要看壁厚、悬垂、支撑、树脂收缩。
- 非流形边 0 也不等于法线全对；CHITUBOX 里看截面/内部视图。
- 如果 STL 很大，浏览器下载和 CHITUBOX 导入都会慢。

## 6. CHITUBOX 参数

| 设置 | 视频值 | 说明 |
|---|---|---|
| 导入比例 | 100 → 10000 | 放大 100 倍；本控制台通常已缩放 |
| 支撑类型 | Cross / Branch | 共享支撑，减少接触点 |
| 支撑粗细 | Light | 微缩模型 |
| 底座高度 | 2.0 mm | 高级设置 |
| 平台接触形状 | 无 | 避免多余几何 |
| 自动抬升 | 关闭 | 视频明确说不需要 |
| 空心 | 大模型 2–3 mm | 小模型可实心 |
| 排液孔 | 最低处 2 个 | 空心必须 |
| 打印时间 | 约 4 小时 | 取决于打印机/层厚/模型 |
| 后处理 | 清洗 + UV 固化 | 按树脂说明 |

### 尺寸检查

导入后先看 CHITUBOX 右下角/对象信息里的尺寸：

- 龙 80 mm 高：合理；
- 龙 0.8 mm 高：比例没改；
- 龙 8000 mm 高：比例改多了（10000 是相对 100 的 100 倍，不是 10000 倍）。

### 支撑检查

- 从最低点开始加；
- 悬垂 > 45° 需要支撑；
- 龙角、尾巴、翅膀尖端重点看；
- 支撑不要穿过细节面；
- 切片后逐层看岛，尤其是第 1–50 层。

## 7. 排错总表

### 7.1 启动/控制台

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击 `AI3D-Print-Flow.exe` 没反应 | SmartScreen/杀软拦截，或缺少 .NET Framework 4.x | 右键 exe → 属性 → 解除锁定；把包体目录加白名单；Windows 10 21H2 / 11 通常自带 .NET 4.x |
| 启动器提示「找不到内置 Node 运行时」 | 只复制了 exe，`runtime\node.exe` 缺失 | 重新解压完整包；exe 必须放在包体根目录，旁边有 `runtime\` 和 `app\` |
| 双击 `start.cmd` 闪退 | Node 缺失/路径错 | 优先改用 `AI3D-Print-Flow.exe`；用 `deploy.cmd` 看报错；确认 `runtime\node.exe` 存在 |
| 浏览器空白 | 前端文件缺失 | 确认 `app/public/index.html` 存在；重启 |
| `EADDRINUSE` | 端口被占用 | 控制台会自动 +1；或 `--port 17870` |
| 页面一直“正在读取本机环境” | 服务未启动/被杀软拦截 | 看命令行窗口；浏览器访问 `http://127.0.0.1:17860/api/health` |
| 点「重新检查」显示 `Failed to fetch` | 本地服务已关闭/连接被重置 | 确认启动窗口还在；重新启动后刷新。仍失败时点连接横幅的「复制诊断信息」，再看 `logs/server.log` 和 F12 Console |
| 页面顶部出现“本地服务连接中断” | 服务重启/窗口被关闭 | 点「重试连接」；或重新双击 `AI3D-Print-Flow.exe` / 桌面快捷方式 |
| 一键部署按钮一直“部署进行中” | 后台任务确实在跑 | 看进度条和日志；不需要可点「取消部署」 |
| 不知道下一步查什么 | 多个组件互相依赖，单个红叉信息不够 | 先点「部署后自检」→「开始自检」，按红色 `fail` 项处理；点「复制报告」保存结论 |
| 设置保存失败 | 配置文件只读 | 检查 `config` 目录权限；删除 `config.json` 重试 |
| 打开文档没反应 | 默认程序未关联 `.md` | 用记事本打开；或装 VS Code/Typora |
| 创建快捷方式失败 | 桌面路径被重定向/权限，或 exe 缺失 | 先运行 `scripts\build-launcher.ps1`；再手动创建；见部署指南第 11 节 |

### 7.2 ComfyUI / 安装

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 一键部署卡在 2% | GitHub ZIP 连接慢 | 等自动重试；或手动下载 ZIP 放到 `installRoot` 后重试 |
| 一键部署卡在安装器阶段 | 安装器内部 curl/pip 正在下载 | 看阶段已用时间；展开日志看最后一行；不要关闭控制台 |
| 一键部署提示 ComfyUI 正在运行 | 8188 有 python 进程 | 关闭 ComfyUI；任务管理器结束 `python.exe`；再点继续 |
| 安装器报 `WARNING: 'ComfyUI-Easy-Install' folder already exists!` 并退出 | 目录已存在但不完整：常见是 `main.py` 在、`python_embeded\python.exe` 被中断或杀软隔离 | v1.4.0 会先把不完整目录改名为 `.incomplete-*` 再运行；若仍失败，关 ComfyUI/`python.exe`/资源管理器窗口，检查火绒/Defender 隔离区，把 `D:\AI3D` 加白后重试。升级后要重启本地服务 |
| 一键部署提示目录不完整 | 上次安装被中断，或 `python.exe` 被隔离 | 看自检 `COMFY_INCOMPLETE` 的 `comfy.missing`；处理占用/隔离后点「继续部署」，旧目录会自动保留 |
| 一键部署在 Torch 阶段失败 | pip 网络/磁盘 | 看日志；确认 45 GB+ 空间；重试或手动运行 Add-ons 的 Torch 2.8 脚本 |
| 一键部署后模型仍缺失 | HF 下载中断，或同名文件大小不足 | 再点继续；自检会列出缺失路径；Qwen 可点「仅下载 Qwen 模型」 |
| 想直接用本机 Ollama / Hugging Face / Stable Diffusion 模型 | 架构和权重文件不同，且文件名不匹配 | 不能直接复用。只硬链接精确同名权重；Qwen-Image 2.1 与 TRELLIS.2 权重仍需单独下载 |
| 下载 ZIP 很慢/失败 | GitHub 网络 | 手动下载，解压到 `installRoot` |
| 安装器找不到 | ZIP 没解压/路径不对 | 确认 `ComfyUI-Easy-Install.bat` 在根目录 |
| 安装器提示 ComfyUI 运行中 | python 进程没退 | 任务管理器结束所有 `python.exe`，关掉 ComfyUI 窗口 |
| `python_embeded\python.exe` 不存在 | 安装没完成，或被火绒/Defender 隔离 | 查隔离区并恢复/加白；重跑安装器。不要只解压 ZIP，旧的不完整目录会保留为 `.incomplete-*` |
| ComfyUI 启动报端口占用 | 8188 被占 | 关掉旧的 ComfyUI；或改 `comfyUrl`/启动参数 |
| ComfyUI 页面打不开 | 还在加载模型 | 等 1–2 分钟；看命令行报错 |
| 节点缺失（红色） | 安装器没跑完 | 重跑 PixelArtistry 安装器；看汇总 |
| 工作流打不开 | 版本不匹配 | 用官方 4 个工作流；不要手改节点 ID |
| 模型缺失 | HF 下载失败 | 按安装器提示的文件名手动下载到 `ComfyUI\models\...` |

### 7.3 Torch / CUDA / WTiVo

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `DLL load failed` | Python/Torch/CUDA 不匹配 | 3.12 / 2.8.0 / 12.8 |
| `CUDA error: no kernel image` | 显卡架构/后端不匹配 | RTX 50 用 50 系构建；RTX 20/30/40 用对应构建 |
| `undefined symbol` | 节点版本冲突 | 重跑官方安装器，恢复 pin 的版本 |
| `out of memory` | 显存不够 | 降预设/代理点；关其他程序；重启 ComfyUI |
| 系统内存爆 | 2K + 25M 代理点 | 32 GB+；或 1.5K |
| WTiVo 很慢 | 代理点多/分辨率高 | 正常；2K 约 3.5 分钟只是 WTiVo 本身 |
| 生成崩溃 | 高代理点 + Quad | 2K 用 bypass；1.5K 降代理点 |

### 7.4 Blender

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `Blender 未找到` | 未装/路径错 | 设置里填 `blender.exe` 完整路径 |
| `Blender 处理失败（退出码 2）` | Python 脚本异常/文件坏 | 看任务栏日志；确认 GLB 可打开 |
| 路径带引号导致找不到 | 复制路径带了 `"` | 去掉首尾引号 |
| 无头模式报插件错 | 第三方插件 | 干净安装/portable |
| 导入 GLB 后是空的 | 文件坏/单位极小 | 在 Blender GUI 里试；检查文件大小 |
| 模型巨大/极小 | GLB 单位问题 | 用目标高度缩放；不要手改比例 |
| 导出 STL 报错 | 选了错误对象/非网格 | 只选网格；Selection Only |
| 碎块删不干净 | 松散块太多 | 提高 `keepLargest` 阈值；手动删 |
| 补洞后仍有边界边 | 洞太大/非流形 | 体素重建；手动补 |
| 体素后变薄壳 | 体素太大/模型薄 | 改 fill 模式；检查壁厚 |

### 7.5 STL / CHITUBOX

| 现象 | 可能原因 | 处理 |
|---|---|---|
| STL 导入后很小 | 比例没改 | 100 → 10000 |
| STL 导入后巨大 | 比例改多 | 恢复 100，或按尺寸算比例 |
| 切片有空洞 | 网格不水密 | 回控制台看边界边；体素重建 |
| 切片缺层 | 法线/薄壳/支撑 | 检查截面；加厚；重新补洞 |
| 支撑太多 | 自动支撑阈值 | 改 Light/Cross；手动删 |
| 支撑穿模 | 支撑参数 | 调接触点/避让；手动加 |
| 打印失败/掉件 | 曝光/支撑/平台 | 做曝光测试；重新加支撑 |
| 表面有纹路 | 层厚/树脂/抗锯齿 | 调层厚；开抗锯齿；后固化 |

### 7.6 网络/下载

| 现象 | 处理 |
|---|---|
| GitHub 443 超时 | 换网络/代理；手动下载；一键部署会自动重试 3 次 |
| Hugging Face 很慢 | 用镜像/手动下载；不要中途关；支持 `.part` 断点续传 |
| 下载到一半失败 | 保留 `.part`，再次点继续即可续传；若提示文件损坏再删除重下 |
| 下载进度不动但日志在走 | 某些安装器内部下载不提供字节数，用阶段动画表示；看日志最后一行 |
| 杀软删了 BAT | 加白名单；从官方仓库重新下载 |

## 8. 日志与诊断

### 8.1 部署后自检（优先）

页面「环境部署」→「部署后自检」→「开始自检」。一键部署成功或失败后也会自动跑一次。它比单纯看环境卡片更直接：

- 明确区分「没有安装」和「安装不完整」：`COMFY_INCOMPLETE` 会指出缺 `ComfyUI\main.py` 还是 `python_embeded\python.exe`；
- 检查 Torch/CUDA、TRELLIS.2/水密节点、PixelArtistry 工作流；
- 逐个检查必需/可选模型，给出目标路径；
- 检查磁盘、内存、GPU、Blender、CHITUBOX 和 ComfyUI 服务；
- 扫描本机 Ollama / Hugging Face 模型，说明哪些不能复用、哪些精确同名权重可硬链接；
- 每项都有稳定代码、原因和 `FIX`。点「复制报告」可保存为文本。

常见自检代码：

| code | 含义 | 先做什么 |
|---|---|---|
| `COMFY_MISSING` | 没找到 ComfyUI 目录 | 一键部署，或手动第 01 步 |
| `COMFY_INCOMPLETE` | 缺 `main.py` 或 `python_embeded\python.exe` | 关闭占用、查杀软隔离区，再点一键部署（会自动改名旧目录） |
| `TORCH_MISMATCH` | Python/Torch/CUDA 不是 3.12 / 2.8.0 / 12.8 | 关闭 ComfyUI，跑 Add-ons 的 Torch 2.8 脚本 |
| `NODES_MISSING` | 缺少 TRELLIS.2 或水密节点 | 关闭 ComfyUI，重跑对应安装器 |
| `WORKFLOWS_MISSING` | PixelArtistry 工作流没写入 | 点「仅写入工作流」 |
| `MODEL_MISSING` / `MODEL_INCOMPLETE` | 模型缺失或文件偏小 | 重跑水密安装器（`AUTO_DL=Y`）或按目标路径手动补 |
| `MODEL_REUSE_AVAILABLE` | 本机有精确同名权重但未就位 | 重新一键部署并勾选「自动复用本机同名模型」 |
| `LOCAL_STACKS` | 本机只有 Ollama/HF 等不兼容模型 | 不能直接复用；按需下载 Qwen / TRELLIS.2 权重 |
| `COMFY_STOPPED` | 组件齐了但 8188 未启动 | 点「启动 ComfyUI」 |

自检报告 `ok:false` 只表示存在 `fail` 项，不代表安装器完全没跑；结合 `comfy` 和 `reuse` 字段看具体缺什么。

### 8.2 控制台日志

- 页面底部任务栏：展开日志，看 Blender/安装器输出。
- 一键部署面板：展开日志，看最近 120 行阶段输出。
- `logs/server.log`：服务异常、全局未捕获错误、500 请求、超过 5 秒的慢请求、客户端断开。
- `logs/` 下的其他任务日志（如有）。
- ComfyUI 命令行窗口：节点报错、OOM、模型加载。
- Blender 报告：`workspace/reports/*.json`。

### 8.2.1 健康检查

```bat
curl http://127.0.0.1:17860/api/health
```

正常返回：

```json
{"ok":true,"app":"ai3d-print-flow","version":"1.5.0","uptime":123,"pid":4896,"node":"v24.21.0","memoryMb":48,"runningJobs":0}
```

如果这里都打不开，先解决本地服务，不要反复点「重新检查」。

### 8.2.2 诊断快照

```bat
curl http://127.0.0.1:17860/api/diagnostics
```

返回版本、PID、Node/平台、内存、路径、脱敏配置、最近任务、`server.log` 尾部 64 KB，以及**最近一次环境检测的分项耗时**：

```json
"checks": {"checkedAt":"...","ready":false,"summary":{"ok":8,"warn":0,"fail":1},
           "timings":{"gpuMs":337,"diskMs":337,"gitMs":861,"blenderMs":309,"totalMs":1178}}
```

`checks` 只返回缓存快照，未检测过时是 `null`——诊断接口本身不会触发探测，所以它在「机器卡住」时也能秒回。页面顶部连接横幅的「复制诊断信息」就是打包这份内容。

判断「检测为什么慢」：`totalMs` 高但 `gpuMs` 很低，多半是 Git 探测或 models 目录太大；`blenderMs` 高说明 Blender 启动慢（首次加载或插件过多）。

### 8.2.3 错误码

所有失败响应统一为 `{ ok:false, code, status, error, hint }`。`code` 是稳定值，可以据此判断原因，不必依赖中文文案：

| code | 状态码 | 含义 | 怎么办 |
|---|---|---|---|
| `E_INVALID` | 400 | 参数非法（配置越界、路径不存在、文件头不符、JSON 不合法） | 按 `error` 里的提示改正后重试 |
| `E_BUSY` | 409 | 同类任务正在运行（安装类共用一把锁） | 等任务结束，或先在任务栏点「取消」 |
| `E_UNKNOWN_ACTION` | 400 | 动作名不存在（多见于旧页面缓存） | 刷新页面；仍不行就重启控制台 |
| `E_TOO_LARGE` | 413 | 上传超过上限（图片 40 MB / GLB 4 GB） | 压缩或换用二进制格式 |
| `E_CONTENT_TYPE` | 415 | 操作请求不是 `application/json` | 用页面或脚本按 JSON 提交 |
| `E_FORBIDDEN` | 403 | Host/Origin 校验失败 | 只用 `127.0.0.1` / `localhost` 访问 |
| `E_NOT_FOUND` | 404 | 任务或文件不存在 | 刷新后重试 |
| `E_DISK_FULL` | 507 | 磁盘空间不足（含 ENOSPC） | 清理磁盘或改安装目录，断点会保留 |
| `E_INTERNAL` | 500 | 未预期错误 | 看 `logs/server.log`，或用诊断快照反馈 |

Node 自身的错误码（`ENOENT`、`EBUSY` 等）不会出现在 `code` 里，避免与 API 契约混淆。

## 9. 性能与时间预期

以下只是量级，不是承诺：

| 步骤 | RTX 4090 / 5080 量级 | 低端 8 GB 量级 |
|---|---|---|
| Qwen 2K 出图 | 约 1 分钟（首次加载更久） | 可能 3–8 分钟或 OOM |
| TRELLIS.2 单图 3D | 约 10–12 分钟 | 更久，可能降分辨率 |
| WTiVo 1.5K | 约 2 分钟 | 3–5 分钟 |
| WTiVo 2K | 约 3.5 分钟 | 不建议 |
| Blender 后处理 | 10 秒–2 分钟 | 1–5 分钟（面数多） |
| CHITUBOX 切片 | 1–5 分钟 | 更久 |
| 光固化打印 | 约 4 小时（视频） | 取决于打印机 |

首次运行会加载模型，时间明显更长；第二次开始会快。

## 10. 重置与恢复

### 10.1 重置控制台配置

删除：

```text
config/config.json
```

重启控制台，会从 `config/default.json` 重新生成。

### 10.2 重置工作流

删除：

```text
ComfyUI\user\default\workflows\PixelArtistry\AI3D_*.json
```

然后用控制台重新生成。不要删官方 4 个工作流，除非你要重装。

### 10.3 重置节点

关闭 ComfyUI，重跑 PixelArtistry 安装器。它会恢复到测试过的版本。

### 10.4 重置 ComfyUI

如果环境彻底乱了：

1. 备份 `ComfyUI\models` 和 `ComfyUI\output`；
2. 删除 `D:\AI3D\ComfyUI-Easy-Install`；
3. 重新跑 Easy Install；
4. 重装 TRELLIS.2 和 PixelArtistry。

模型很大，能不重下就不重下。
