# v1.2.0 优化记录（47 项）

> 本版本聚焦「可交付、可恢复、可验证」。以下是实际落到代码里的 47 项编号优化，不是计划清单；检测、前端与交付的补充加固列在文末。
> 完整 ComfyUI / Torch / TRELLIS.2 / 模型下载仍需在目标机器上跑完；本机已验证本地服务、安全策略、下载续传和任务状态逻辑。

## 一、安装与下载

1. **Git 探测不再依赖 PATH**：`findGit()` 同时检查 `where.exe git.exe`、`C:\Program Files\Git\cmd\git.exe`、`C:\Program Files (x86)\Git\cmd\git.exe` 和用户级安装目录；检测到 Git 后自动跳过官方安装器的 Git 升级步骤。
2. **下载自动重试**：连接失败、HTTP 408/429/5xx、流中断都会按指数退避重试，最多 5 次；重试时从 `.part` 的实际大小继续。
3. **HTTP Range 断点续传**：使用 `Range: bytes=<have>-`，正确处理 206、200（服务器忽略 Range 时从头写）、416（断点等于远端大小时直接提升，断点更大时丢弃重下）。
4. **断点元数据防串包**：`.part.json` 记录 URL、ETag、Last-Modified 和总大小；URL 或 ETag 变化时自动丢弃旧断点，避免把两个文件的字节拼在一起。
5. **连接与停滞双超时**：30 秒连接超时、60 秒无数据停滞超时；停滞会中断当前流并重试，而不是永远卡住。
6. **磁盘空间预检**：下载前按远端总大小估算剩余空间；安装盘不足时给出「还差多少 / 当前剩多少 / 断点会保留」的可操作提示。
7. **临时文件清理**：下载失败保留 `.part` 供续传，成功后才 rename；上传失败删除 `.part`；解压失败自动删除损坏 ZIP 并重新下载一次。
8. **ComfyUI ZIP 损坏恢复**：首次 `Expand-Archive` 失败时，删除 ZIP、重新下载、再次解压；仍失败才抛出带 stderr 尾部的错误。
9. **一键部署磁盘阈值**：基础部署要求约 30 GB，勾选 Qwen 后要求约 55 GB；低于阈值在 preflight 阶段就停止，不浪费下载时间。
10. **Qwen 下载独立预检**：按缺失模型估算空间，已完整下载的模型跳过；单个模型失败不会删除已完成的其它模型。
11. **残留 `.auto.bat` 清理**：每次一键部署前删除上次异常退出留下的自动安装脚本，避免执行到过期内容。
12. **ComfyUI 已运行检测**：启动前先请求 `/system_stats`；已在运行时直接返回，不再重复拉起进程。

## 二、任务与恢复

13. **取消语义修正**：取消后子进程通常以非 0 退出，`done()` / `fail()` 不会再覆盖 `cancelled` 状态，不会出现「已取消又变红」。
14. **任务输出上限**：stdout/stderr 只保留尾部 256 KB，任务日志最多 800 行，前端只取最近 400 行，防止长安装把内存吃满。
15. **ANSI / 回车进度处理**：清理 ANSI 颜色码，同时按 `\n`、`\r\n`、`\r` 切分，winget / pip 的原地进度行也能进入日志。
16. **超时兜底**：子进程超时后先 `taskkill /T /F`；若 10 秒内仍不退出，任务以超时失败结束，不再永久挂起。
17. **任务并发保护**：一键部署、Qwen 下载、单项安装、ComfyUI 启动、Blender 后处理分别加互斥；重复点击返回已有任务或明确提示。
18. **任务查询不再只看前 12 条**：`hasRunning()` 直接遍历任务表，运行中的长任务不会因为列表截断而被漏掉。
19. **任务列表扩容**：状态接口返回最多 30 条任务，页面刷新后仍能重新接上正在运行的一键部署。
20. **页面刷新自动重连任务**：初始化时优先找 `install.oneclick` 的运行任务，再退回到任意运行任务；重新进入页面不会丢失进度。

## 三、配置与安全

21. **配置白名单校验**：只接受 `installRoot`、`comfyuiRoot`、`blenderPath`、`chituboxPath`、`workspaceDir`、`preset`、`targetHeightMm`、`repairMode`、`decimateRatio`、`port`、`comfyUrl` 和四类 last* 字段；未知键直接 400。
22. **配置值边界**：端口限制 1024–65535；高度 0–2000 mm；减面 0–0.95；预设和修复模式枚举校验；ComfyUI URL 只允许 http/https。
23. **相对路径规范化**：安装根目录、ComfyUI 根目录、工作目录为空或相对路径时统一解析为绝对路径，避免从不同启动目录运行得到不同结果。
24. **原子写入与备份**：先写 `config.json.tmp-<pid>` 再 rename；写入前保留 `config.json.bak`；损坏 JSON 自动隔离为 `config.json.corrupt-<时间>`。
25. **原型污染防护**：`__proto__` 等未在白名单中的键会被拒绝；加载旧配置时逐键过滤，不让未知字段进入运行时对象。
26. **HTTP 安全头**：所有响应带 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Cross-Origin-Resource-Policy: same-origin`；HTML 带 CSP。
27. **Origin / Host 校验**：只允许 `127.0.0.1`、`localhost`、`[::1]`；带 `Origin` 的请求必须与 Host 同源，跨站请求直接 403。
28. **JSON Content-Type 校验**：`/api/action` 只接受 `application/json`，`text/plain` 等简单请求返回 415，配合 Origin 校验阻断跨站表单。
29. **上传限制**：图片 40 MB、GLB 4 GB；先看 `Content-Length`，再在流式写入时二次计数；超限删除临时文件并返回 413。
30. **上传/下载安全**：上传先写随机临时文件再原子替换；`/api/file` 与 `/api/download` 只允许工作目录内的路径，支持 Range 206/416 和 `Content-Disposition` 下载。
31. **静态缓存与日志轮转**：静态资源带 ETag / Last-Modified，支持 304；JS/CSS 每次 revalidate，HTML 不缓存；`server.log` 超过 5 MB 自动轮转 `.1`–`.3`，避免日志无限增长。
32. **优雅关闭**：SIGINT/SIGTERM/SIGBREAK 时取消后台任务、停止接收新连接、关闭空闲连接，给在途请求 1.5 秒收尾，最多等待 5 秒退出；`/api/shutdown` 需要自定义请求头，普通跨站表单无法触发。
33. **单实例复用**：启动时先探测同端口的 `/api/health`；如果同版本的 AI3D 服务已在运行，直接打开现有页面并退出，不再启动第二个控制台或自动换到 17861。只有端口被其他程序占用时才顺延端口。

## 四、追加优化（34–47）

34. **429 / Retry-After 精确退避**：下载遇到 429 或 5xx 时优先遵循服务器 `Retry-After`（秒数或 HTTP 日期），最多等待 60 秒；没有该头才退回指数退避，避免被远端限流后继续高频重试。
35. **Windows 文件替换重试**：新增 `replaceFile()`，对杀毒软件、索引器、资源管理器预览造成的 `EPERM` / `EBUSY` / `EACCES` 做退避重试；下载完成和上传落盘都走同一套替换逻辑。
36. **文件流异常保护**：静态文件与工作区文件的读取统一走 `pipeFile()`；文件在响应途中被移动/删除时记录日志并结束响应，不再产生未处理的流错误；客户端断开时主动销毁读取流。
37. **HEAD 与下载文件名兼容**：`/api/file`、`/api/download` 支持 HEAD、Range 206/416；`Content-Disposition` 同时提供 ASCII 回退名和 UTF-8 `filename*`，中文文件名在旧浏览器里也不会变成空名。
38. **上传魔数校验**：PNG、JPEG、WebP、GLB 在落盘后校验文件头，扩展名与真实内容不符时返回 400；避免把任意文件伪装成图片或模型送进 Blender/ComfyUI。
39. **服务诊断快照**：新增 `GET /api/diagnostics`，返回版本、PID、Node/平台、内存、路径、脱敏后的公开配置、最近任务和 `server.log` 尾部 64 KB，便于一次性定位启动失败、端口冲突和任务异常。
40. **前端一键复制诊断**：连接横幅新增「复制诊断信息」，剪贴板 API 被拒绝时回退到 `execCommand('copy')`；仍失败则自动下载 `ai3d-diagnostics-*.txt`，不会只剩一句 `Failed to fetch`。
41. **安全头补强**：新增 `Permissions-Policy`、`Cross-Origin-Opener-Policy`、`X-DNS-Prefetch-Control`；CSP 增加 `form-action 'self'`，进一步限制跨站表单和权限调用。
42. **静态资源更新不吃旧缓存**：JS/CSS 改为 `Cache-Control: no-cache`，并在 `index.html` 使用 `?v=1.2.0` 版本查询串；同版本覆盖安装后刷新页面即可加载新前端，不必清理浏览器缓存。
43. **关闭流程补强**：Windows 下响应 `SIGBREAK`；关闭时调用 `closeIdleConnections()`，1.5 秒后再强制关闭残留连接，避免 keep-alive 让控制台窗口卡住。
44. **常驻 HTTP 错误日志**：`server` 增加监听后的错误处理器，运行期 HTTP 错误写入 `server.log`；启动阶段的 `EADDRINUSE` 仍由原有逻辑处理，不会重复刷屏。
45. **错误状态与磁盘提示**：`/api/action` 保留业务错误的状态码，磁盘写满时返回 507 并提示「清理磁盘/修改安装目录，断点会保留」；不再把所有失败都压成 400。
46. **打包版本一致性**：`package.ps1` 校验 `package.json`、`index.html`、`README.md` 的版本号一致；`verify-package.ps1` 额外检查诊断接口、`Permissions-Policy`、CSP `form-action`，并确认包内 `workspace/` 不含用户文件。
47. **回归测试扩展**：`smoke-test.mjs` 覆盖诊断、HEAD、Range 206、下载头、上传魔数、304 与安全头；`test-download.mjs` 覆盖 429 `Retry-After` 重试。下载续传、任务取消、配置校验和 HTTP smoke test 均可在本机复跑。

## 五、检测、前端与交付（补充）

- **检测并发**：环境检测把 nvidia-smi、磁盘、Git 一起并行跑；ComfyUI Torch 探测和服务端口探测并行；Blender 版本探测与 ComfyUI 检查并行。
- **检测去重**：同一时刻多个 `/api/checks` 请求复用同一个 in-flight Promise，避免重复启动 nvidia-smi / python。
- **可配置端口显示**：ComfyUI 服务状态不再硬编码 `8188`，从 `comfyUrl` 解析实际端口。
- **前端超时分级**：启动任务 45 秒，文件选择 180 秒，环境检测 180 秒；任务轮询 10 秒且不叠加内部重试。
- **任务轮询退避**：运行中 900 ms、页面隐藏 3 秒；连接断开最多重试 20 次（指数退避），并提示「任务可能仍在后台运行」。
- **上传进度**：改用 XHR `upload.onprogress` 显示真实百分比；前端与服务端都校验扩展名和大小。
- **无障碍**：跳过导航链接、`progressbar` ARIA 值、`aria-live` 状态、焦点陷阱、Esc 关闭设置、`aria-expanded` 日志按钮、减少动画支持。
- **CLI 增强**：新增 `deploy [--qwen]`，`check` 有阻塞项时返回退出码 2；任务日志按增量打印，不再每次重复全部日志。
- **健康检查**：`/api/health` 返回版本、PID、Node 版本、内存、运行任务数，便于判断「页面打不开是服务没起还是检测失败」。
- **打包可验证**：`scripts/package.ps1` 生成 `PACKAGE_INFO.json`，排除 `.bak`/`.corrupt-*`/`.tmp-*`/`.part`；`scripts/verify-package.ps1` 解压后实际启动服务并验证健康检查、CSP、Origin 403、Content-Type 415。
- **回归测试**：`scripts/test-download.mjs`、`test-jobs.mjs`、`test-config.mjs`、`smoke-test.mjs` 全部通过。

## 六、已知未验证项

- 本机没有跑完整的 ComfyUI → Torch 2.8 → TRELLIS.2 → PixelArtistry 安装链路；需要目标机器实际网络、磁盘和 UAC 环境验证。
- Qwen 约 25 GB 模型没有实际下载完；下载器逻辑已用本地断流/续传/416 场景测试。
- `Failed to fetch` 的原始根因未复现；当前版本通过连接横幅、自动重试、`/api/health`、`/api/diagnostics`、一键复制诊断信息和 `logs/server.log` 提供可操作提示。
