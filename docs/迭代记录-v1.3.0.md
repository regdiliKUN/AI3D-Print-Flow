# v1.3.0 迭代记录（25 轮）

> 起点是 v1.2.0（已完成 47 项优化）。本轮不再堆新功能，而是把「能跑通」收紧为
> **出错时说得清、修得回、验得了**：修掉会卡死控制台的真实缺陷，补齐可观测性与历史产物，
> 把验证手段从 4 个脚本扩到 9 组，并把散落在 4 处的版本号收敛到 1 处。
>
> 每一轮都写明：**本轮目标 / 具体改动 / 改进理由 / 自检结果**。
> 自检命令均在本机（Windows 10 19045 · RTX 4090 · Blender 5.2.2 LTS · Node 24.21.0）实际执行。

## 第 1 轮：安装动作抛错导致任务永久卡住

**目标**：消除「点一次安装失败后，所有安装都被挡住」的死锁。

**改动**
- `app/server.mjs`：新增 `runInlineJob()`，统一「创建任务 → 执行 → 落 done / 落 fail」。
- `install.comfy.run`、`install.torch28.run`、`install.trellis.run`、`install.pixel.run` 四个动作改走该包装。
- 这四类动作补上 `assertIdle('install', …)`，避免一键部署期间又弹出第二个安装器。
- `HEAVY_JOB_TYPES` 提为模块常量（原来每次调用都新建一个 Set）。

**理由**
`jobs.create()` 之后直接调用 `runComfyInstaller()`，一旦它抛错（未找到安装器、目录缺失），
异常被外层 catch 转成 400 响应，但任务对象仍是 `running`。而 `assertIdle()` 正是靠
「有没有 running 任务」来互斥的——于是这个幽灵任务会把后续所有安装挡死，直到重启服务。
这是「用一次就废」级别的缺陷。

**自检**：在临时沙箱（配置指向空安装目录）里依次调用四个动作：

```
install.comfy.run   -> 400 未找到 ComfyUI-Easy-Install.bat，请先下载并解压。
install.torch28.run -> 400 未找到 Torch 2.8.0 切换脚本…
jobs: install:error ×4 · running=0
retry after failures -> 400（不再提示「任务正在进行中」）
```

## 第 2 轮：文件名清洗可被绕过

**目标**：让「客户端提供的文件名」无法影响落盘位置与文件名合法性。

**改动**
- `safeName()` 重写：拒绝 `.` / `..` / `...`；去掉尾部点与空格；拦截 Windows 保留设备名
  （`CON`/`NUL`/`COM1`/`LPT1` 等，含带扩展名的形式）；超长名截断但保留扩展名。
- 上传处理新增目录包含校验：`isInside(destDir, dest)`，纵深防御。

**理由**
实测 `safeName('..')` 原样返回 `..`，而 `join(destDir, '..')` 就是父目录——上传接口的
`name` 参数由客户端控制，等于给了一条逃出 `workspace/input` 的路径。
`a.png.` 这类名字在 Windows 上会被系统截成 `a.png`，随后 `statSync('a.png.')` 失败返回 500。
`CON` 之类则根本无法创建。

**自检**：17 组用例全部通过，含 `'..\\..\\etc\\passwd' → 'passwd'`、`'nul.png' → '_nul.png'`、
`300 字符 + .safetensors → 150 字符且保留扩展名`。

## 第 3 轮：CLI 反复重印日志

**目标**：终端里的日志每行只出现一次。

**改动**
- 新增 `app/lib/report.mjs`，导出 `createJobReporter()`：用「已打印行的 key 集合」去重，
  集合过大时按当前窗口重建，避免无限增长。
- `cli.mjs` 的 `deploy` 与 `postprocess` 共用该实现（原来是两份重复代码）。

**理由**
`publicJob.logs` 永远是日志**尾部**，每次任务更新都会把整窗日志重发一遍。
原实现只记住「最后一行」，于是每次更新都把前面几行再打一次；12 次更新会打出约 40 行。

**自检**：模拟 12 次更新、窗口仅 5 行——打印 12 行、去重后仍 12 行、重复投递同一快照 0 新增。

## 第 4 轮：后台刷新覆盖用户输入

**目标**：用户改过的参数不会被后台状态刷新改回旧值。

**改动**
- `app.js` 新增 `touched` 集合，`renderSelections()` 跳过被手改过的字段
  （目标高度 / 修复模式 / 减面比例 / GLB 路径）。
- `refreshState()` 不再调用 `renderSettings()`——设置抽屉只在打开时填充。
- 保存设置成功后清空 `touched`，让新默认值生效。
- 新增 `setSelectValue()`：配置里出现下拉框没有的值（如 `cli config set decimateRatio=0.6`）时
  动态补一个「自定义」选项，而不是静默回落到第一项。

**理由**
上传图片、任务结束、点「重新检查」都会触发 `refreshState()`。原来它无条件把
`config.targetHeightMm` 写回输入框——用户填了 135 mm，上传一张图就被改回 80 mm，
而且没有任何提示。

**自检**（Playwright + 无头 Chromium）：填 135 → 触发刷新 → 仍为 135；选 voxel → 仍为 voxel；
抽屉里填路径 → 刷新后仍在；重载页面 → 回到 80；`decimateRatio=0.6` 正确回填。

## 第 5 轮：后处理参数静默兜底

**目标**：非法参数要报错，而不是被悄悄当成 0。

**改动**
- `runPostprocess()` 用 `numberOption()` 严格解析目标高度（0–2000）与减面比例（0–0.95）；
  修复模式给非法值直接报错。
- 目标高度为 0 时，结果里追加一条明确告警（保持原有「不缩放」行为，但不再沉默）。

**理由**
`clamp(Number(x) || 0, 0, 2000)`：`''`、`'abc'`、`undefined` 全部变成 0，
而 0 的语义是「不缩放」——导出的 STL 保持 Blender 单位，在 CHITUBOX 里只有几十毫米的
千分之一。这正是排错文档里最高频的问题，却是被自己的代码静默制造出来的。

**自检**：`'abc'` / `5000` / `-5` / `magic` / `2` / `-1` 六种非法输入全部抛出带字段名的中文错误；
合法参数正常进入 Blender 调用。

## 第 6 轮：上传与临时文件卫生

**目标**：上传失败或进程崩溃后不留垃圾，缺 `Content-Length` 时也不半路 ENOSPC。

**改动**
- `util.mjs` 新增 `cleanupStaleTemp()`：按模式 + 24 小时阈值清理。
- 服务启动时清扫 `workspace/input`、`workspace/glb`、`config` 下的 `.upload-*.part`、
  `config.json.tmp-*`，并写日志。
- 上传的空间预检：有 `Content-Length` 按实际值 + 200 MB；没有则要求至少 512 MB 可用。

**理由**
上传走的是「随机临时文件 → 原子替换」，进程被杀时临时文件会留在工作区；
配置写入同理。原来完全没有清理路径。另外 chunked 上传没有 `Content-Length`，
原代码直接跳过空间检查，结果写到一半才 ENOSPC。

**自检**：预置 2 天前的 `.part` 与 `config.json.tmp-999` → 启动后被清掉并写日志；
刚创建的 `.part` 保留；正常上传仍然成功。

## 第 7 轮：静默覆盖已有文件

**目标**：任何「写文件」动作都不应无声覆盖别人的东西。

**改动**
- `placeInputImage()`：注入到 `ComfyUI/input` 时，若同名文件尺寸不同，改名
  `AI3D_<原名>_<时间戳>.ext`；尺寸相同视为同一张图，复用不复制。
- `uniqueWorkflowPath()`：生成的工作流若同名已存在，追加 `_2`、`_3`。
- 写入失败时给出「ComfyUI 可能占用了同名文件」的提示。

**理由**
`ComfyUI/input` 是用户和 ComfyUI 共用的目录，直接 `copyFileSync` 会覆盖别的工作流正在用的图。
另一个更隐蔽：`timestamp()` 只到秒，同一秒内连点两次「生成工作流」，
第二个文件会覆盖第一个——用户可能已经在 ComfyUI 里打开了它。

**自检**：同名不同尺寸 → 生成 `AI3D_existing_20261023_030229.png`，原文件字节数不变，
`LoadImage` 指向新名；同尺寸 → 不产生副本；同一秒两次生成 → `…json` 与 `…_2.json` 并存。

## 第 8 轮：模型探测的 12 次全树遍历

**目标**：环境检测不再对 models 目录重复遍历。

**改动**
- `checks.mjs` 新增 `buildModelIndex()` + `createModelLookup()`：惰性建一次索引
  （文件名小写 → 路径），12 个模型规格共用；命中预期路径时连索引都不建。
- 移除已无用的 `findFile` 引用。

**理由**
`modelPath()` 在预期路径不存在时调用 `findFile(modelsRoot, [file], 4)`——一次完整 BFS。
12 个模型规格里，未安装的可选模型（Qwen 4 个、Pixal3D、MoGe）每次都会触发一次失败的
全树遍历。装了多个模型包的用户，models 目录往往上千个文件。

**自检**：构造 8 分类 × 25 子目录 × 60 文件（12,000 个文件）的模型树，
两种实现结果完全一致，中位耗时 **520.8 ms → 47.7 ms（10.9×）**。

## 第 9 轮：最新 GLB 导入

**目标**：少一次系统调用，且不把「正在写入」的文件复制成半截。

**改动**
- `findLatestGlb()`：`statSync` 由两次（mtime、size）合并为一次；跳过 0 字节文件。
- 扫描加上限 `GLB_SCAN_LIMIT = 20000`：`ComfyUI/output` 可能堆了上万张预览图，
  原来会无界遍历，点一次「导入最新 GLB」就卡几秒。
- 导入后校验目标大小与源大小一致，不一致直接报「GLB 正在写入，请稍后再点」。
- 顺带把两处 `await import('node:fs')` 改为顶层静态导入。

**理由**
ComfyUI 保存 GLB 是流式写入，用户看到文件出现就点「导入最新 GLB」时，很可能拿到半截文件，
之后 Blender 报一个和真实原因无关的解析错误。动态 import 在热路径上还多一次模块解析。

**自检**：预置 空 / 旧 / 新 三个 GLB → 选中 `newest.glb`、跳过 0 字节文件、
复制后大小 300 B 与源一致、`lastGlb` 写入配置。

## 第 10 轮：版本号单一来源 + 动作参数不再静默兜底

**目标**：版本号只有一个可写位置；用户传错参数时得到明确报错。

**改动**
- `paths.mjs` 的 `VERSION` 改为读取 `package.json`（失败回落 `0.0.0`，不抛错）。
- 下载器的 `User-Agent` 改用 `VERSION`（原来是 `AI3D-Print-Flow/1.2`）。
- `index.html` 去掉 `?v=1.2.0` 查询串与页脚硬编码版本，页脚改为 `<span id="appVersion">`，
  由 `/api/state` 的 `version` 填充。
- `folder.open`：未知 `target` 原来静默回落到 `map.workspace`（点错就打开错的目录），
  改为报「未知目录标识：x。可用：…」。
- `workflow.preparePixel` / `prepareQwen`：`preset` 用 `assertPreset()` 校验，
  非法值不再被悄悄换成 1.5K / 2K；`seed` 必须是 0 以上整数；`prompt` 上限 4000 字符。

**理由**
同一个版本号原先出现在 `package.json`、`paths.mjs`、`index.html`（2 处）、页脚、
`deploy.ps1`、`package.ps1` 里。发版时漏改一处，界面就会长期显示旧版本。
去掉查询串是安全的：静态 JS/CSS 已是 `Cache-Control: no-cache` + 内容 ETag，升级后刷新必然重新校验。

**自检**：`/api/health` 与 `package.json` 一致（1.3.0）；HTML 中不再有 `?v=x.y.z`；
页脚渲染出 `v1.3.0`；`app.js` 仍带 `no-cache`；
`folder.open {target:'nope'}` → 400「未知目录标识」；`preset:'4k'` → 400「显存档位」；
`seed:-3` → 400「随机种子」；4001 字符提示词 → 400「提示词过长」；合法参数正常生成。

## 第 12 轮：Blender 进度与失败报告

**目标**：进度条反映真实阶段；失败时留下可诊断的证据。

**改动**
- `blender/postprocess.py`：新增 `progress(pct, msg)`，在十余个真实阶段打印
  `[AI3D] PROGRESS <百分比> <阶段>`；新增 `write_report()`；`main()` 拆成
  `main()`（异常兜底）+ `run(opt)`（主流程），异常时写出 `ok:false` 的报告（含 traceback）。
- 导入后检查多边形总数为 0，直接报「GLB 里没有可打印的面」。
- 导出阶段改为 90/94，把最后的 96/100 留给控制台的 STL 校验，避免进度条先到 100 又倒退。
- `postprocess.mjs`：只解析结构化标记，删掉原来按中文字符串猜进度的正则；
  失败时优先用报告里的 `error` 作为异常信息。

**理由**
原来靠 `line.includes('导入')` 之类猜阶段：改一句文案进度条就永久卡住；
体素重建可能跑几分钟，界面却停在 50%。失败时 Blender 只吐一段 stderr 尾部，
用户拿不到完整原因，也没有报告可回看。

**自检**（真实 Blender 5.2.2 无头运行，合成的 0.2 m 立方体 GLB）：

```
PROGRESS 15 已导入 1 个网格 → 22 → 26 → 34 → 40 → 72 → 80 → 90 → 94
缩放系数 399.999994 → 80.0 mm
水密：是 · 尺寸 80×80×80 mm · 三角面 12 · 体积 512.00 cm³ · 边界边 0
```

失败路径（伪造的 GLB）：报告写入 `{"ok": false, "error": "GLB version must be 2…", "traceback": …}`，
CLI 直接显示该错误并给出报告路径。

## 第 13 轮：STL 判定与单位诊断

**目标**：格式判定不再误判；「模型太小」在源头被指出。

**改动**
- 读取前 2 KB 文本，同时看「是否以 solid 开头」与「是否含 `facet normal`」，
  再结合字节数是否精确匹配二进制布局来判定。
- ASCII STL 上限由 120 MB 降到 48 MB，并说明原因（整文件读入 + 正则，内存是文件数倍）。
- 新增 `unitSuspicion`：最大尺寸 < 1 mm 时置真，`note` 里给出具体做法；
  `postprocess.mjs` 同步把它变成一条 warning。

**理由**
二进制 STL 的 80 字节 header 允许写任意内容，有些导出器会写 `solid ...`；
原实现只要字节数对得上就按二进制解析，但 ASCII 文件恰好撞上「declared 数值使总长接近」时
就会误判成二进制并解析出乱数据。

**自检**：二进制 12 面 / 水密 / 80 mm / 体积 512000 mm³；header 以 `solid` 开头的二进制仍判为 binary；
ASCII 与二进制体积一致；0.08 mm 立方体触发单位告警；非 STL 内容报「无法识别的 STL 格式」。

## 第 15 轮：历史产物

## 第 18 轮：错误码契约

**目标**：错误可被程序判断，而不只是给人看。

**改动**
- 新增 `app/lib/errors.mjs`：`AppError`、`ERROR_CODES`、`errorPayload()`。
- 所有失败响应统一为 `{ ok:false, code, status, error, hint }`；`code` 由
  `AppError.code` 或状态码映射得到，**Node errno 不会被当作 API 错误码**（`ENOSPC` 特判为 `E_DISK_FULL`）。
- `assertIdle()` 抛 `E_BUSY` + 409，未知动作抛 `E_UNKNOWN_ACTION`。

**理由**
原先靠 `err.status` 加中文文案判断。文案一改，任何依赖它的脚本或提示都会失效；
而「任务忙」「磁盘满」「参数错」三种情况在界面上应该有不同引导。

**自检**：未知动作 400 `E_UNKNOWN_ACTION`、错误 Content-Type 415 `E_CONTENT_TYPE`、
非法 JSON 400 `E_INVALID`、伪造图片 400 `E_INVALID`、41 MB 上传 413 `E_TOO_LARGE`、
`ENOSPC → E_DISK_FULL/507`、`ENOENT → E_INVALID/400`（不泄漏 errno）、500 → `E_INTERNAL` 带提示。

## 第 23 轮：引擎级异常不再被当成「参数错」

**目标**：4xx 与 5xx 分流正确，且意外异常必须进日志。

**改动**
- `errors.mjs`：`errorPayload()` 自己决定状态码（不再由调用方强制 400）——
  `AppError` 用自己的、带 `status` 的用该值、`ENOSPC` 用 507、
  `TypeError`/`ReferenceError`/`RangeError`/`SyntaxError`/`URIError` 用 500，
  其余（校验类 `Error`）仍用 400。
- `appCode()`：未登记的状态码按「4xx → `E_INVALID`、5xx → `E_INTERNAL`」兜底，
  修掉 422 这类状态码被映射成 `E_INTERNAL` 的错位。
- `/api/action` 的 catch 不再强制 400；`status >= 500` 时补 `logError()`，带堆栈进 `server.log`。
- 新增 `scripts/test-errors.mjs`（9 组断言），并接入 `test-all`。

**理由**
`errorPayload(err, { status: Number(err?.status) || 400 })` 意味着动作里任何异常都是 400。
于是 `TypeError: x is not a function` 会被报成「参数错」，用户按提示改参数永远改不好；
更糟的是动作的 catch 完全不写日志，真正的 bug 连堆栈都没留下。
校验类错误在本包里是 `throw new Error('中文提示')`，靠错误类型区分是安全的。

**自检**

```
ok   AppError 保留自身状态码 → 409 E_BUSY
ok   校验类普通错误 → 400 → 400 E_INVALID
ok   TypeError → 500 内部错误 → 500 E_INTERNAL
ok   未登记的 4xx 仍给 E_INVALID → 422 E_INVALID
ok   未登记的 5xx 给 E_INTERNAL → 503 E_INTERNAL
错误契约测试 OK
```
