# 多模态输入说明（v2.0）

> 这条工作流的传统入口是「先在图库里找到一张 AI 生成的图，再拖进 TRELLIS.2」。
> v2.0 把入口扩成三种：**一句话、一张图、一个 `.txt` 提示词文件**，并且在写进
> ComfyUI 之前就把「这张图能不能转出可用网格」说清楚。
>
> 所有分析都在本机完成：文件头解析、像素统计、提示词整理都不联网；只有你主动
> 配置并点击「用视觉模型写提示词」时，图片才会发给你自己指定的本地模型服务。

---

## 1. 三种输入方式

| 输入 | 适合 | 入口 | 产物 |
|---|---|---|---|
| 文字 | 还没有图，想直接生成 | 「文字 → 图片」卡片 | 规范化提示词 → Qwen-Image 2.1 工作流 |
| 图片 | 已有生成图，或想用参考图 | 拖入 / 点选 / `Ctrl+V` 粘贴 | 图片分析 + 水密工作流 |
| `.txt` / `.md` | 提示词写在别处，或想复用模板 | 「导入 .txt 提示词」 | 填入主体与风格输入框 |

三种输入最终都汇合到同一条链路：

```text
文字 / 图片 / 文本文件
        ↓
提示词规范化（单一主体 + 一体化底座 + 可打印细节）
        ↓
Qwen-Image 2.1 出图  ──或──  直接使用已有图片
        ↓
TRELLIS.2 单图转 3D
```

## 2. 提示词工作台

### 2.1 为什么没有「负向提示词」输入框

内置的 Qwen-Image 2.1 工作流使用 **CFG = 1**。在这个设置下，负向提示词不会参与
采样，提供一个输入框只会让用户以为它生效了。因此页面把「规避项」并入**正向**
提示词，写成自然语言：

```text
一条盘踞在圆形底座上的东方龙, 鳞片清晰, 单一紧凑主体, 居中构图, 正面视角,
干净的纯色背景, 轮廓清晰, 细节实心可打印, 带一体化底座, 不要出现：多个主体、
文字、水印、复杂背景、半透明材质、悬空碎片
```

这也是该工作流模板自带示例的写法。页面底部的「模型实际收到的提示词」显示的
就是最终写进工作流的文本，不是输入框原文。

### 2.2 自动规避规则

`buildPrompt()` 会扫描主体、风格、规避项三部分（先去掉 `no text`、`不要文字`
这类否定短语，避免规则误伤），命中后给出提醒并自动追加规避项：

| 代码 | 触发例子 | 级别 | 处理 |
|---|---|---|---|
| `MULTI_SUBJECT` | 多个、两个、一群、场景 | warn | 追加 `multiple subjects` |
| `TEXT_IN_IMAGE` | 文字、水印、logo、字幕 | warn | 追加 `text` |
| `NON_PRINTABLE_MATERIAL` | 透明、玻璃、发光、粒子 | warn | 追加 `transparent, glowing` |
| `THIN_FEATURE` | 链条、飘带、头发丝、薄膜 | warn | 只提醒，不追加（可能正是设计的一部分） |
| `BUSY_BACKGROUND` | 背景、街道、森林 | info | 追加 `busy background` |

这些规则**不会阻止提交**。它们的作用是解释「为什么这个描述容易翻车」，
最终是否继续由你决定。

### 2.3 模板与种子

- 五个模板：微缩雕像、生物 / 怪物、机械 / 机甲、道具 / 摆件、建筑 / 场景。
  点一下只填充风格与空着的主体，不会覆盖已经写好的文字。
- 随机种子：留空时工作流使用随机种子；填入整数可复现同一张图。页面上的
  「随机」按钮会生成一个新的 15 位整数。
- 字符上限 4000（与 Qwen 侧一致）。输入框计数到 95% 时变黄，超过时服务端
  返回 `E_PROMPT_TOO_LONG`，而不是静默截断。

### 2.4 导入提示词文件

支持 `.txt` / `.md` / `.markdown`，上限 512 KB。读取规则：

- 第一行作为「主体描述」；
- 其余行作为「风格与细节」；
- 只有一行时，整段同时作为主体，并回填到风格框。

上传的原文会保存在 `workspace/text/`，方便回看。若文件前 512 字节包含 NUL
字节，会被判定为二进制文件并拒绝，避免把乱码塞进输入框。

## 3. 图片适配度分析

分析分两层：服务端只看**能确定的事实**，浏览器再补**像素级统计**。任何一层
失败都不会阻断主流程。

### 3.1 服务端：文件头（不依赖第三方库）

`readImageHeader()` 直接解析：

- PNG：签名 + `IHDR` 的宽高、位深、色彩类型；按块解析 `tRNS`，不会把
  IDAT 压缩数据里恰好出现的 `tRNS` 字节误判成透明通道。
- JPEG：逐段扫描到 `SOF0/1/2`，读出真实宽高；EXIF 再大也不会把尺寸读错。
- WebP：`VP8X` / `VP8 ` / `VP8L` 三种容器都能读出宽高与 alpha 标志。

扩展名可以随便改，文件头不会。把 WebP 改名成 `.png` 会直接返回
`E_IMAGE_INVALID`，并提示重新导出。

### 3.2 浏览器：像素统计

页面把图片画到 128×128 的 canvas 上，统计：

| 指标 | 含义 | 用来判断 |
|---|---|---|
| `subjectCoverage` | 与四角背景色差明显的像素占比 | 主体太小 / 太满 |
| `borderTouch` | 画面边缘 3 px 内有内容的比例 | 主体是否被裁切 |
| `sharpness` | 拉普拉斯响应平均值 | 是否模糊、过度降噪 |
| `contrast` | 亮度标准差 | 抠图边界是否稳定 |
| `transparentShare` | alpha < 16 的像素占比 | 大面积透明 |

canvas 只读取本地 `/api/file` 返回的图片，不上传、不跨域、不写入磁盘。

### 3.3 评分与分级

服务端先给 100 分，按以下规则扣分，浏览器统计再继续扣：

| 情况 | 扣分 | 级别 |
|---|---|---|
| 短边 < 256 px | −45 | risk |
| 短边 < 档位建议值（1K 640 / 1.5K 900 / 2K 1200） | −18 | warn |
| 画幅比 > 2.2 或 < 0.45 | −22 | warn |
| 画幅比 > 1.7 或 < 0.6 | −8 | warn |
| 每像素字节数 < 0.1（压缩过重） | −10 | warn |
| 主体占比 < 6% 或 > 88% | −12 / −8 | warn |
| 主体触边 > 25% | −10 | warn |
| 锐度 < 3 | −8 | warn |
| 对比度 < 14 | −6 | info |

最终分数 0–100，分三级：

- **ok（合适）**：可以直接转网格；
- **warn（可改进）**：可以继续，但按建议调整效果更好；
- **risk（不建议）**：低于 60 分或命中致命项，建议先换图。

评分只是启发式判断，不是「像不像可打印模型」的视觉理解。真正的语义判断
留给可选的视觉模型。

### 3.4 候选池

- 一次可拖入多张，或直接 `Ctrl+V` 粘贴截图；默认保留最近 8 张。
- 同名文件不会覆盖，自动追加 6 位短后缀。
- 缩略图角标就是适配度分数；灰/黄/红对应 ok / warn / risk。
- 点缩略图切换「当前使用」的图片；点 × 只从候选池和 `workspace/input`
  移除，不碰其它目录。删除失败时缩略图会回到原位。
- 键盘可用：缩略图是 `role="option"` 的可聚焦节点，Tab 进入列表后按
  Enter / Space 选图；删除按钮是独立 `<button>`，可单独聚焦。
- 刷新页面后候选池会从 `workspace/input` 重建，并在后台按当前档位自动补评分，
  一次只处理一张，避免同时解码多张大图；切换档位会隐藏旧分数并重新计算。
- 缩略图与原图通过 `/api/file` 的 ETag 缓存：文件没变时只返回 304，不重复传输
  整张图；文件被替换后大小或修改时间变化，ETag 自动失效。

## 4. 可选：视觉模型（看图写提示词）

### 4.1 它解决什么问题

「这张图不错，但我想改一点再生成」——以前只能凭感觉重写提示词。接一个本地
视觉模型后，可以先把图反推成结构化的「主体 / 风格 / 细节」，改几个词再交给
Qwen，形成 **图 → 文字 → 图 → 3D** 的闭环。

### 4.2 支持的服务

任何 OpenAI 兼容的 `/v1/chat/completions` 端点，例如：

| 服务 | 地址 | 说明 |
|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | 需要先 `ollama pull qwen2.5vl:7b` |
| LM Studio | `http://127.0.0.1:1234/v1` | 在 Server 页启动本地服务 |
| 其它 | 自填 | 必须支持 `image_url` 形式的 base64 输入 |

在「设置 → 视觉模型」里填写地址与模型名，点「检测连接」或「保存设置」。模型名
留空时，服务端会从 `/models` 列表里优先挑名字含 `vl`、`vision`、`llava`、
`minicpm`、`gemma3` 等关键词的模型；显式填写的模型名会直接使用，即使它没有出现
在 `/models` 列表里（部分推理服务会隐藏模型列表）。

需要鉴权的远程端点可在同一区域填写 API Key。密钥只写入
`config/config.json`，`GET /api/state`、`config.save` 响应和诊断信息都只返回
`vlmHasKey` 布尔值，不回显明文；留空保存表示保持原密钥，点「清除密钥」才会删除。

### 4.3 行为与边界

- 地址留空 = 明确关闭。页面显示「未配置」，隐藏「用视觉模型写提示词」按钮，
  不会在后台探测端口。
- 探测超时 1.8 秒（设置页手动探测 2.5 秒），不可用只降级、不报错。
- 单张图片上限 6 MB；超过时返回 `E_VLM_TOO_LARGE`，提示先缩到 2048 px。
- 单次识别超时 90 秒；识别失败返回稳定错误码，不会把半截文本写进输入框。
- 返回内容优先按 JSON 解析（兼容 ```json 代码块、`subject/style/detail` 与
  中文字段）；不是 JSON 时再按三行解析 `主体：` / `风格：` / `细节：`。两者都
  失败时，第一行作为主体，其余留空，不会丢内容。
- 图片只发送给你填写的地址。控制台自身不代理、不转发、不记录 base64。

### 4.4 本机实测

在 Windows 10 + Ollama + `qwen2.5vl:7b`（Q4_K_M）上，用一张 1024×1024 的
角色转面图实测：

```text
主体：戴珍珠项链的女性雕像，手托下巴，底座有徽章
风格：光滑，细腻，柔和，均匀光照
细节：头发纹理，珍珠项链，徽章，服装褶皱，底座细节
耗时：约 38 秒（首次加载模型）
```

小模型会把「参考图排版」误读成「雕像」，这是 7B 视觉模型的能力边界；它的
价值是给你一个可编辑的起点，而不是替你做最终判断。

## 5. 接口与错误码

### 5.1 新增动作

| 动作 | 参数 | 返回 |
|---|---|---|
| `image.inspect` | `path`, `preset` | 尺寸、格式、评分、findings |
| `image.pool` | `limit` | 最近输入图片列表 |
| `image.forget` | `path` | 从 `workspace/input` 删除 |
| `prompt.build` | `subject`, `style`, `avoid`, `preset`, `material`, `scaffold` | 规范化提示词、警告、字符数 |
| `vlm.status` | `timeoutMs` | 端点、模型列表、可用性 |
| `vlm.caption` | `path`, `prompt` | 结构化的主体 / 风格 / 细节 |

`GET /api/state` 现在同时下发 `presets`、`limits` 与 `features.multimodal`，
页面上的档位数字、上传上限、候选池大小都来自服务端，不再前后端各写一套。

### 5.2 新增错误码

| 代码 | HTTP | 含义 |
|---|---|---|
| `E_IMAGE_INVALID` | 400 | 文件头无法解析，或扩展名与实际格式不符 |
| `E_IMAGE_TOO_SMALL` | 400 | 预留：分辨率低于硬性下限 |
| `E_IMAGE_TOO_LARGE` | 400 | 文件超过 40 MB，或单边 > 20000 px / 总像素 > 100 MP |
| `E_IMAGE_MISSING` | 400 | 图片已被移动或删除 |
| `E_PROMPT_EMPTY` | 400 | 主体描述为空 |
| `E_PROMPT_TOO_LONG` | 400 | 最终提示词超过 4000 字符 |
| `E_PATH_OUTSIDE` | 403 | 路径不在 `workspace` 内 |
| `E_GLB_INVALID` | 400 | GLB 不完整或格式错误 |
| `E_VLM_OFFLINE` | 400 | 视觉模型地址为空、连不上或超时 |
| `E_VLM_NO_MODEL` | 400 | 服务在线但没有任何模型 |
| `E_VLM_TOO_LARGE` | 400 | 图片超过 6 MB |
| `E_VLM_BAD_RESPONSE` | 400 | 模型返回 HTTP 错误或空内容 |

### 5.3 安全边界

- 所有图片 / 文本路径必须位于 `workspace` 内；`..`、绝对路径越界一律 403。
- 上传仍校验文件头：PNG / JPEG / WebP / GLB / 纯文本。
- 文本上传会拒绝前 512 字节含 NUL 的文件。
- 页面未捕获异常通过 `POST /api/client-log` 写入 `logs/server.log`，单条
  message 截断 500 字符、stack 截断 4000 字符，请求体上限 64 KB。
- 视觉模型请求由服务端发出，页面拿不到 base64，也不会把密钥写进前端。

## 7. 已知限制

- 图片分析是启发式的：它能判断分辨率、画幅、压缩、主体占比与锐度，但
  不能判断「这个造型是否可打印」。悬空结构、过薄特征仍需人看。
- 像素统计依赖 canvas。极老的浏览器或禁用 canvas 时只显示服务端结论。
- 候选池只保留最近 8 张的**界面列表**，`workspace/input` 里的文件不会自动
  删除；长期使用需要自己清理。
- 视觉模型的能力取决于模型本身。7B 级模型能给出可编辑的描述，但会误读
  排版、文字和小道具；重要项目建议用更大的 VL 模型，或人工核对后再生成。
- `.txt` 导入按「第一行主体 / 其余风格」切分。若你的提示词是一整段，建议
  手动拆分后再导入，效果更稳定。
